ACCELERA / THE GUIDE

A clear path through
an operational exception.

Accelera is a student prototype for OCBC IGNITE Problem Statement 2. It shows how a defined routine exception can move from investigation to a permitted action and a verified outcome.

All organisations, instructions, confirmations, mandates and invoices are fictional. There are no live bank connections, funds transfers or outgoing messages.

1. Record and detect

Payment intake validates the instruction against synthetic reference records. Correct matching details are recorded without calling the exception investigator. Missing or conflicting details are flagged for a person.

2. Investigate the case

The workspace connects the original instruction, source confirmation, internal enquiry and any existing mandate. It shows the specific question preventing resolution. Optional live AI provides advisory investigation; without a key the app clearly labels an offline deterministic walkthrough.

3. Check permission

Structured checks govern the action. Exact reference, customer, beneficiary, amount and currency must match. Authority must be current and permit those fields. Reviewer approval cannot substitute for missing evidence or a missing mandate.

4. Apply the defined update

The status playbook updates only an internal mock enquiry. Allocation recovery restores an existing authorised invoice split with reviewer approval. Original payment instructions are protected. An unresolved previous attempt blocks a blind retry.

5. Read back before closure

The app rereads saved records and compares them with the expected outcome and protected payment fields. Acknowledgement without a saved update stays open. Repeating a successful action does not apply the allocation again.

Who does what?

  • System: detects and records the exception.
  • Agent: assembles evidence and prepares the permitted next action.
  • Reviewer: approves the existing authorised proposal or takes ownership.
  • Administrator: inspects the actions, actors and verification history.
  • Process Owner: measures observed prototype outcomes.

The role selector explains these responsibilities. It is a demonstration view, not a claim of production access control.

Start with these scenarios.

  • Normal payment: standard validation; no exception investigation.
  • Stale enquiry status: exact confirmation permits a defined internal status update.
  • Missing confirmation: request evidence, wait and resume when the simulator supplies it.
  • Authorised allocation: approve and recover the existing S$2,000 + S$500 invoice split.
  • False acknowledgement: the service acknowledges, the record stays unchanged, and verification catches it.
  • Human attention: conflicting or unsupported cases remain open with a specific question.

Advanced fixtures cover a missing mandate, an already-applied allocation, a mismatched confirmation and an in-flight attempt. Simulator controls are always labelled.
